# 2026-11-19 — baseline

The first measurements of the skill, taken while adding `round-close.sh`,
`new.sh`, the send-back limit, the lean `claude` delegate and the README's
data-oriented form. Claude Code 2.1.327; the skill from `9be98ed` to
`f5dc16d`; delegates on Haiku 5.5.

Three projects, named here by letter:

| Project | TASKs | Campaigns | Closed rounds |
|---|---|---|---|
| A | 320 | 20 | 76 |
| B | 63 | 14 | 28 |
| C | 28 | 2 | 8 |

## 1. Do closed rounds hold what the MANAGER's prose asks?

**Method:** `tools/closed-rounds.sh <root>` — `scripts/round-close.sh` on every
closed round. (A first pass, before the script existed, ran the same checks by
hand and found the same rows.)

| Line of `round-close.sh` | A | B | C |
|---|---|---|---|
| problem: a row not done, blocked or dropped | 37 | 0 | 1 |
| problem: a send-back line with no cause of the set | 94 | 6 | 6 |
| problem: "Checks" with no command and its output | 0 | 2 | 2 |
| note: a validated TASK with no review file | 156 | 40 | 22 |
| note: a TASK past 2 send-backs | 1 | 0 | 0 |

**Reading:**
- Of A's 37 open rows, 35 are older vocabulary in the State column (27
  `done (<hash>)`, 8 `validated`) and 2 are rows left `running` in a closed
  round. C's one is a row left `todo`. **3 real rounds closed with a row
  open.**
- One TASK of A had 3 send-backs against the prose's limit of 2: an
  exception the user authorized, the work being right.
- "No cause of the set" and "no review file" are rounds older than the
  closed set of causes and than the mandatory review; they are not
  regressions.
- Two shapes of a row that a check must allow, both legitimate: `TASK-a
  rejected; TASK-b → <commit>` and `TASK-a → TASK-b` (judge by the last TASK).

**Decision:** `round-close.sh` (`9be98ed`); the send-back limit as 2 in prose,
3 to 5 on the user's word, the 6th refused by `delegate.sh`.

**Re-measure:** rounds closed after `9be98ed` should give `ok`; a problem line
there is a hole in the script or in the prose.

**Reading:** 37 of the 41 classified lines are gaps of the TASK, written by

## 3. How much of a delegate's input is fixed context?

**Method:** `tools/delegate-usage.sh ~/.claude/projects/*/` — every session a
delegate ran, from its transcript. A transcript logs each content block of a
response as an entry with the response's usage repeated: requests are counted
once per message id. A first pass that counted entries gave requests and input
about 2.5 times too high; its shares were right, since both sides were
inflated alike.

| Roles | Requests | Fixed (1st request) | Input | Output | Fixed share |
|---|---|---|---|---|---|
| DEV+TESTER | 40 | 27,595 | 5,844,115 | 123,889 | 18% |
| DEV+TESTER | 34 | 27,945 | 4,014,172 | 94,210 | 23% |
| DEV+TESTER | 30 | 25,212 | 2,333,308 | 41,340 | 32% |
| DEV+TESTER | 24 | 24,350 | 1,784,041 | 48,090 | 32% |
| DEV+TESTER | 21 | 27,600 | 1,491,695 | 33,160 | 38% |
| DEV+TESTER | 17 | 24,361 | 970,677 | 20,839 | 42% |
| DEV+TESTER | 17 | 24,357 | 843,828 | 22,650 | 49% |
| DEV | 15 | 24,335 | 873,762 | 36,427 | 41% |
| DEV | 5 | 20,665 | 120,076 | 1,406 | 86% |

**Reading:** the fixed context — system prompt, tool definitions, instruction
files — is 18% to 49% of a TASK's input; the rest is the work itself (files
read, test output), the same in any harness. Nearly all of the fixed part is
read from cache.

## 4. What does a lean delegate save?

**Method:** `tools/fixed-context.sh <root>` from project A — two `claude -p`
calls of one word on Haiku, as `delegate.sh` ran before `24fdced` and with
`--tools "Read,Edit,Write,Bash,Grep,Glob" --strict-mcp-config
--disable-slash-commands`.

| Run | Input tokens | Cost at API prices |
|---|---|---|
| full | 27,693 | $0.0038 |
| lean | 15,873 | $0.0022 |
| saved | 11,820 (43%) | 42% |

What is left in the lean 15.9k: the system prompt with six tools (about 9.6k:
11.3k measured in a project with no instruction files of its own, less the
global `CLAUDE.md`), the user's global `CLAUDE.md` (about 1.7k), project A's
`AGENTS.md` (about 3k) and about 1.6k besides. File sizes are bytes / 4.

Applied to section 3: about **10%** of the input of a TASK of 34 requests and
**21%** of one of 17.

**Decision:** the lean flags and a usage line in `delegate.sh` (`24fdced`).
`--bare` would cut more, but reads only `ANTHROPIC_API_KEY`, never the
subscription's OAuth (`claude --help`, 2.1.327).

**Re-measure:** the fixed share of delegates after `24fdced` in section 3's
terms (expected about 16k in project A); `fixed-context.sh` again after a
Claude Code update.

## 5. Does a lean delegate still do the work?

**Method:** a throwaway project, a one-line TASK made with `new.sh`, run with
`delegate.sh ... claude haiku`, then reviewed the same way.

| Delegation | Outcome | Requests | Input | Output | Time |
|---|---|---|---|---|---|
| execute (DEV) | `done`; criterion `pass`; one file changed; Environment: none | 5 | 72,779 | 2,205 | 13 s |
| review (REVIEWER) | `validate`; file made by `new.sh`; two low findings | 9 | 253,089 | 6,995 | 39 s |

Zero permission denials, empty stderr, in both. `delegate.sh`'s usage line,
from `--output-format json`, agreed with the transcript within 2%. Not
covered: a mutation through `mutate.sh` (the TASK added no condition) and the
`agy` path.

## 6. How often does the unfilled-placeholder check cry wolf?

**Method:** `scripts/task-preflight.sh <root> TASK-nnn --no-run`, section
`unfilled:`, on every TASK of A, B and C, and on a TASK fresh from `new.sh`.

**Reading:** a fresh TASK lists each `<…>` and each choice left. Of the 411
real TASKs, 9 (2.2%) are flagged, each the TASK's own text: a backticked
`<name>` or `<path>` the code takes. Spans of code that hold more than a
placeholder are ignored; a span that is exactly one cannot be told apart.
